## 1. 目的と背景

### 目的

**行きたい国の観光地・文化・ニュースを題材に、英語のリーディングとリスニングを楽しく練習できる Web アプリを作る。**
同時に、旅行先の下調べもできるようにする。

### 背景

- 英語学習は「必要性を感じにくい」「続かない」ことが多い。
- 「行ってみたい国のこと」は、学習内容そのものが興味の対象になるので、続けやすい。
- ゲームのような仕掛け（世界一周、スタンプ、バッジ、キャラクター）で、「楽しい」を引き出す。

### 成功の目安

| 指標 | 目安 |
|---|---|
| 初めての人が、説明なしで最初の記事を読み終えられる | ○（スマホ・PC の両方で） |
| 1 つの国を最後までクリアして、スタンプをもらえる | ○ |
| 「もう 1 本読みたい」と思える演出になっている | 触ってもらって確認する |

## 2. 対象ユーザー

| 項目 | 内容 |
|---|---|
| 主な利用者 | 海外旅行に興味がある、英語が少し苦手〜中程度の日本語話者（中高生〜社会人） |
| 英語レベル | A2〜B2（CEFR）。初級（A2）・中級（B1）・中上級（B2）から選ぶ |
| 利用場面 | 通学・通勤中のスマホ、自宅の PC |
| 前提知識 | 英語の文章を辞書を引きながら読める程度。アプリの使い方の説明は不要にする |

## 3. コンセプト

| 項目 | 内容 |
|---|---|
| ひとこと | 「世界一周しながら、英語が読める・聞ける」 |
| 世界観 | 旅行・パスポート・スタンプ・搭乗券。温かく、少しレトロな旅行ポスターの雰囲気 |
| 配色 | 紺（#14233a）・夕焼けオレンジ（#e2703a）・クリーム（#f5f1e8）を基調に、ティール・マスタードを差し色にする |

## 4. スコープと担当

### 4.1 担当

| 担当 | 受け持つ範囲 |
|---|---|
| フロント | 画面、操作、見た目、演出（キャラクター・効果音・BGM） |
| バックエンド | HTTP の API、採点・スタンプ・バッジなどのルール、DB |
| API | Wikipedia・Gemini・YouTube との連携、記事と問題の生成、初期教材（seed） |

### 4.2 今回の範囲

| 区分 | 内容 |
|---|---|
| **作る** | 6.「画面一覧」の画面と、5.「機能要件」のうち MVP・次 |
| **対象の国** | **Python の DB に入っている 4 か国・12 か所だけ**（イギリス・フランス・カナダ・オーストラリア）。決定済み。DB の内容は `database/insert_countries.py` と `insert_trips.py` |
| **当面作らない** | **ログイン・ユーザー登録**（ID・パスワードによる認証）。決定済み |
| **作らない** | ネイティブアプリ、管理画面、他言語（英語・日本語以外）への対応 |

### 4.3 前提

- フロントは素の JavaScript（ES Modules）で作る。ビルド工程は使わない。
- サーバーがまだ無い間は、モック（`LocalApi`）でフロントだけを動かす。
- 外部 API のキーが無くても、手書きの初期教材で全機能が動く。

## 7. 非機能要件

| 項目 | 要件 |
|---|---|
| 対応端末 | **スマホ（縦向き）を優先**。PC は最大幅 960px の中央寄せ。幅 360px のスマホで崩れない |
| 対応ブラウザ | 最新の Chrome・Safari・Edge・Firefox |
| 表示速度 | 画面の切り替えは 1 秒以内を目安。0.15 秒以上かかるときだけ「読み込み中」を出す（チラつき防止） |
| 通信 | 通信の失敗でアプリが固まらない。失敗時は FR-61 の表示 |
| アクセシビリティ | キーボードで操作できる。フォーカスの位置が見える。文字と背景のコントラストを確保する。画像には代替テキストを付ける。FR-55 を守る |
| 安全性 | **サーバー由来・ユーザー入力由来の文字列は必ずエスケープして表示する**（XSS 対策）。API キーをフロントのコードに置かない |
| 保守性 | 層（ui / application / domain / infrastructure）を守る。画面から直接 `fetch` しない。CSS の色・余白は変数（`tokens.css`）から使う |
| 動作モード | サーバーあり（`HttpApi`）と、サーバーなし（`LocalApi`）を、`main.js` の 1 行で切り替えられる |
| 素材の権利 | 画像・キャラクター・音は、**自分たちで作ったもの、または商用利用できるもの**だけを使う。キャラクターは自作の絵から作る |
| 容量 | 画像・音を合わせて、初回の読み込みが重くなりすぎないようにする（BGM は読み込みを遅らせる） |

## 8. データと API の概要

詳細な URL と JSON の形は、設計書の「API の約束」と `frontend/js/domain/models.js`、`frontend/js/infrastructure/api/ApiClient.js` に書きます。ここでは、機能と API の対応だけを書きます。

| 機能 | API（案） | 状態 |
|---|---|---|
| FR-01 国の一覧 | `GET /api/countries` | フロント実装済み（モック） |
| FR-02 国の詳細 | `GET /api/countries/{countryId}` | フロント実装済み（モック） |
| 外部 API の利用可否 | `GET /api/status` | フロント実装済み（モック） |
| FR-10〜13 記事・採点 | `GET /api/trips/{tripId}/lesson`、`POST /api/lessons/{lessonId}/grade` | 未着手 |
| FR-30・31 ニュース | `GET /api/countries/{countryId}/news`、`POST /api/news/{newsId}/grade` | 未着手 |
| FR-20・21 単語 | `GET /api/words/lookup`、`GET/POST/DELETE /api/words` | 未着手 |
| FR-05 行きたい | `PUT/DELETE /api/wants/{tripId}` | 未着手 |
| FR-41・43 バッジ・履歴 | `GET /api/badges`、（履歴の取得先は未決） | 未着手 |

### 共通のルール（案）

| 項目 | ルール |
|---|---|
| JSON のキー | `camelCase` |
| エラー | `{ "error": { "code": "...", "message": "画面にそのまま出せる日本語" } }` |
| 日付 | 日付は `"2026-10-14"`、日時は `"2026-10-14T20:15:00"` |
| 答え | 問題を返すときは、正解（`answer`）と解説（`explanation`）を**含めない**。採点結果で初めて返す |
| 報酬 | 採点で新しく得たスタンプ・バッジは `rewards` に入れて返す |
| 外部 API | 使えないときは、手書きの初期教材に自動で切り替える |

> フロントのコードの `TODO(API)` / `TODO(Backend)` が、各担当への依頼です。`grep -rn "TODO(" frontend/` で一覧できます。

## 11. 受け入れ基準（完成の目安）

MVP が完成したと言える条件です。

- [ ] ホームから国を選び、記事を開いて読み、4 択に答えて、採点結果を見られる
- [ ] 採点前に、正解と解説が画面にもネットワークの応答にも含まれていない
- [ ] 通信に失敗したとき、日本語のメッセージと「再読み込み」が出る
- [ ] ブラウザの「戻る」で、前の画面に戻れる
- [ ] 幅 360px のスマホと、PC の両方で崩れない
- [ ] サーバーなし（モック）で、上の流れがすべて動く
- [ ] `main.js` の 1 行を変えるだけで、本物のサーバーに切り替わる
- [ ] サーバー由来の文字列をすべてエスケープして表示している
